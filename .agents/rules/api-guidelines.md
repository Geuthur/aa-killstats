# API & OpenAPI Guidelines

When working on backend communication and frontend API integration in this repository, strictly adhere to the following rules:

## 1. Always use `openapi-fetch` (Never `axios` for API calls)

- All API requests to backend endpoints must use `openapi-fetch` (`apiClient` exported from `@/Api/Api`).
- Do **not** use `axios` for API calls or endpoints. `apiClient` already handles CSRF tokens (`X-CSRFToken`), credentials, base URLs, and TypeScript types.

## 2. Automatic OpenAPI Generation on Backend API Changes

Whenever you modify or add backend API endpoints, Ninja schemas (`schema.py`), or models that affect the API:

- **Autonomously run `make react-openapi`**:

  - The AI agent **MUST automatically and autonomously execute** `make react-openapi` immediately after making backend API changes.
  - Do not wait or ask the user for permission to run this command — execute it proactively so the frontend types stay in sync with the backend.

  ```bash
  make react-openapi
  ```

  *(Ensure the Python virtual environment is active, e.g. `VIRTUAL_ENV=/home/voicesofwar/venv make react-openapi`)*.

- **NEVER manually edit `frontend/src/Api/OpenApi.ts`**:

  - Direct manual edits to `frontend/src/Api/OpenApi.ts` are strictly forbidden.
  - This file must **only** be generated by `make react-openapi`.

- **Workflow Summary**:

  1. Modify backend API endpoint, schema, or model.
  1. Autonomously execute `make react-openapi` to update `frontend/src/openapi.json` and regenerate `frontend/src/Api/OpenApi.ts`.
  1. Implement or update frontend components using the freshly generated types from `@/Api/OpenApi`.
